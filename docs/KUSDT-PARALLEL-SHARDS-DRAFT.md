# kUSDT 轮次的 256 片并行设计

同一轮最多支持 **256 个并行售票分片**（按需创建），按**三类 UTXO 分工**：

- **管理 UTXO**：创建者出 **`4 KAS`** 状态押金（终局销毁时 100% 退还创建者）；只负责创建轮次、登记新开分片、封盘汇总、决定开奖还是退款、开奖（含超时重掷锚点）并下发终局指令；全程不持有、不消费任何 kUSDT 金库。
- **账本 UTXO（最多 256 片，按需创建）**：各片独立 CID，由**该分片第一个买家**在买票时创建并垫付本片状态押金（销毁时全额退还该首购买家）；负责买票、派奖和小额退款（仅 1～2 票轮次）。
- **金库 UTXO（KCC-20，每片 1 个）**：与账本 UTXO 分离，在该片首购时同步建立；金库归对应账本 UTXO 控制（`OWNER_COVENANT_ID`，禁用 borrow），**消费金库必须同时输入对应账本 UTXO**。

用户始终使用一个入口，看到全轮票数、奖池、唯一开奖结果和自己的退款进度；购票时前端允许用户选择**优先使用已有分片**或**自建新片**。每轮**固定票价（最低 `1 kUSDT`，即 `1,000,000` 最小单位）**、**0 抽成**（奖池 100% 归赢家，仅第三方执行者推奖时每片扣固定 `0.5 kUSDT` 激励）、**允许单笔买 `1..N` 票**（单笔占 1 条记录，每片上限 256 条购买记录，全轮最多 65,536 笔购买记录）；封盘**按到期时间 `closeDaa` 触发**。

## 创建与买票

创建者只需出 **`4 KAS`** 管理 UTXO 押金即可开轮，确定轮次身份、固定票价（`>= 1 kUSDT`）与到期时间 `closeDaa`，无需预建空分片。

- **开新片（首笔买票，单笔完成）**：买家选择新建分片并购买 `qty` 票（`qty >= 1`）时，在**同一笔交易**中同时消费管理 UTXO 与买家资金，一次性完成建片与首购，并由管理 UTXO 执行 3 道链上防假记录校验：
  1. **亲手组装唯一初始账本**：管理 UTXO 不接受外部任意账本字节，而是在合约内直接拼出初始账本（`OPEN` 态、`manager_cid`、轮次参数、首购买家退押金公钥、硬编码记录数 `= 1` 与恰好 1 条首购记录 `[qty, buyerPk]`），校验新分片输出匹配 `P2SH(initLedger + shardOpenTail)`、硬编码正版 `SHARD_OPEN_TEMPLATE_HASH` 以及 `2 KAS` 账本押金。
  2. **同笔只读校验真 kUSDT 入库**：管理 UTXO 用 `shard_cid = OpOutputCovenantId(1)` 读出新分片 CID，只读校验金库输出满足 `OpOutputCovenantId(2) == kUSDT_CID`、`2 KAS` 金库押金，以及正版 KCC-20 模板的 `owner == OWNER_COVENANT_ID(shard_cid)`（禁用 borrow）和 `amount == qty * price`（精确等于首购票款）。管理 UTXO 仍不持有、不消费任何 kUSDT。
  3. **登记名册**：管理 UTXO 将 `shard_cid` 写入合法分片名册（上限 256 片）。
- **已有分片买票（第 2～256 条记录）**：完全不经过管理 UTXO，只使用本片账本、对应金库和买家资金，各分片并行互不阻塞。账本脚本核对金库身份、代币家族、入账量（`qty * price`）与找零，票款入账与登记买家公钥在同一交易完成。

## 身份绑定与定位（多独立 CID）

链上不保存不断变动的分片地址或 outpoint，全部通过共识层终身不变的 **Covenant ID（CID）** 完成双向绑定：

1. **一轮多 CID（创世派生）**：开新片交易中，管理 UTXO 后继走延续分支保留 `manager_cid`，新分片账本走创世分支获得全新的独立 `shard_cid`（`shard_cid != ZERO && shard_cid != manager_cid`，共识层按 `authorizing_input.outpoint` 与输出校验，见 `rusty-kaspa` `covenants.rs`）。
2. **管理 ↔ 分片双向记 CID**：
   - **管理记分片**：管理 UTXO 通过 `OpOutputCovenantId` 读出新 `shard_cid` 写入合法名册（每片 32B，满载 256 片为 8,192B），封盘与下发按名册顺序核对，防假分片与漏片。
   - **分片记管理**：分片账本头固定记录 `manager_cid`（32B），开片时由管理 UTXO 校验写对，封盘与接收终局指令时只认 `OpInputCovenantId(0) == manager_cid`，防假管理片劫持。
3. **分片 ↔ 金库双向绑定（防串片盗刷）**：
   - 各片金库的 KCC-20 `owner` 直接锁死为 `OWNER_COVENANT_ID(shard_cid)`（禁用 borrow）。消费 A 金库时，KCC-20 合约强制要求交易输入包含 `CID_A`，B 账本（`CID_B`）或管理 UTXO 均会被共识直接拒绝。
   - 分片账本在买票、派奖、退款时反向校验配对金库的 `kUSDT_CID`、`owner == OWNER_COVENANT_ID(shard_cid)` 与余额（`票数 × 票价`）。
4. **链下定位与正版合约验真（Profile / 模板哈希）**：
   - **判断管理合约是否正版**：正版管理合约与分片合约编译后的模板哈希（`templateHash`）固定公开并固化在合约互引、前端与 Indexer 的 Profile 中。前端/Indexer 校验管理 UTXO 创世（及当前）`redeemScript` 的 `P2SH` 匹配、`templateHash == 官方 MANAGER_TEMPLATE_HASH` 以及初始参数合法（`openedCount == 0`、正版 `kUSDT_CID` 等）；篡改任意 1 字节都会导致模板哈希不匹配而被拒认。
   - **一次验真、全程保真**：正版管理合约内部硬编码了所有合法后继模板哈希，创世验真后中途无法被替换成假合约，因此分片链上只需校验 `OpInputCovenantId(0) == manager_cid`。
   - **定位最新 UTXO**：前端与执行者通过节点 `utxoindex`（按 Covenant ID 索引未花费 UTXO）或 Indexer 按 `shard_cid` 查找该片当前最新账本与金库 UTXO。

## 封盘与全轮决定（消除抽奖失败）

各已开分片到达可封盘时间后停止售票，进入冻结态（保留本片账本与原金库不变）。管理 UTXO 核对每片身份与冻结状态，按固定片序汇总**全部已开分片**（未开的分片不存在，无需汇总空片）。汇总完成后：

- **0 票**（未开任何分片）：管理 UTXO 直接结清，退还创建者押金。
- **1～2 票**：进入小额正常退款（全轮最多退 2 笔，不受 KCC-20 3 输出上限拖累）。
- **满 3 票**：进入开奖，抽签固定唯一赢家后向各已开分片下发派奖指令。

为避免“抽奖失败 → 大规模异常退款”，开奖阶段做两项改造：
1. **消除拒绝采样失败**：采用无拒绝取模或固定顺序确定性重试，使开奖算法 100% 必出结果。
2. **超时重掷锚点（替代异常退款）**：在原锚点 `d + 100` 之后的保护期（沿用现行 **12 小时 / `432,000 DAA`**）内只允许按原锚点开奖，禁止重掷；仅当超过保护期全网仍无人提交开奖证明时，允许管理 UTXO 原地自更新一次（票数与分片名册完全不变），换取新的 `outpoint` 与未来 `新 DAA + 100` 锚点重新开奖，避免锚点超出节点裁剪窗口导致死锁。

管理 UTXO 在**封盘汇总**与**终局下发**两个阶段均采用**游标顺序分批、同交易直接更新账本 UTXO**（全程不碰金库 UTXO，也不产生额外凭证 UTXO；`COLLECT` / `DRAW` / `REROLL` / `DISPATCH` 的极小 KAS 矿工费均由**调用方自付**，不扣管理押金）：
1. **分批封盘汇总（`COLLECT`）**：管理 UTXO 维护游标 `collectedCount`（`0 → openedCount`）。每批输入 `1 个管理 UTXO + k 个按名册顺序紧接的 OPEN 账本 UTXO`（`1 <= k <= maxBatch`，如 `maxBatch = 8`，由后续 mass 实测定上限），将这 `k` 片切为 `FROZEN` 态并登记其票数与账本承诺。当 `collectedCount == openedCount` 时，管理 UTXO 进入终局决定（0 票结清 / 1～2 票转退款下发 / 满 3 票转 `SEALED` 开奖）。
2. **分批下发终局（`DISPATCH`）**：管理 UTXO 确定赢家或退款决定后，维护游标 `dispatchedCount`（`0 → openedCount`）。每批输入 `1 个管理 UTXO + k 个对应顺序的 FROZEN 账本 UTXO`，直接把这 `k` 片切到 `PAYOUT(winner)` 或 `REFUND` 态（切完即可立即并行派奖/退款，无需等剩余批次）。最后一批完成（`dispatchedCount == openedCount`）时，管理 UTXO 在同笔交易中直接销毁，将管理押金退还创建者。

## 派奖与小额退款

**V1 采用「单片独立派奖（执行者激励）+ 赢家自推兜底」，不做跨片合并**；派奖与小额退款均由各片账本 UTXO 消费自身对应的金库 UTXO 并行执行：

- **路径 1：第三方执行者激励派奖（固定每片 `0.5 kUSDT`）**
  - 适用条件：本片金库余额 `> 0.5 kUSDT`（6 位小数即 `> 500,000` 最小单位）。
  - 单分片交易原型（3 输入、3 输出，以 `30 kUSDT` 分片为例）：
    - **输入**：本片账本 `A`（`2 KAS`）+ 本片金库 `B`（`2 KAS + 30 kUSDT`）+ 任意执行者普通 KAS `C`（如 `5 KAS`）。
    - **输出**：退还首购买家 `4 KAS`（`2 + 2`，100% 原额退还）+ 赢家 `D`（`1.5 KAS + 29.5 kUSDT`）+ 执行者 `C`（`(3.5 - fee) KAS + 0.5 kUSDT`）。
  - **经济闭环**：发给赢家的 kUSDT 输出承载 KAS（`1.5 KAS`）与矿工费全部由执行者 `C` 垫付，换取固定 `0.5 kUSDT` 激励；首购买家拿回 100% 押金，赢家零操作收奖；完全满足 Trestly 主网 `KCC20.sil` 限制（`MAX_TX_INPUTS = 8`、`MAX_DELEGATES = 2`、`MAX_TOKEN_OUTPUTS = 3`）。[Trestly KCC-20 源码](https://github.com/kaspador/kusdt-open/blob/b70707cd496dc46de4db64d363ccd8e10a029770/covenants-silverscript/KCC20.sil#L224)
- **路径 2：零激励 / 赢家自推兜底（覆盖稀疏分片）**
  - 适用条件：任意 `> 0` 余额分片（含 `<= 0.5 kUSDT` 或激励不足以吸引第三方执行者的稀疏分片）。
  - 交易结构（3 输入、2 输出，以 `1 kUSDT` 稀疏分片为例）：
    - **输入**：本片账本 `A`（`2 KAS`）+ 本片金库 `B`（`2 KAS + 1 kUSDT`）+ 赢家（或任意资助人）普通 KAS `D`（如 `5 KAS`）。
    - **输出**：退还首购买家 `4 KAS`（100% 原额退还）+ 赢家 `D`（`(5 - fee) KAS + 1 kUSDT`，100% 奖池归赢家）。
  - 赢家垫付的承载 KAS 留在自己新生成的 kUSDT 输出中不亏本金，仅付矿工费；且因为 100% kUSDT 归赢家、100% 押金归首购买家，账本脚本无需额外验签。
- **小额正常退款（仅全轮 1～2 票，买家自助领 Pull）**：对应分片切入 `REFUND` 态后，由买家本人发起退款交易（自垫新 kUSDT 输出承载 KAS 与矿工费，承载 KAS 留在自己钱包不亏本金），领回原额 kUSDT；该片所有票退完清空金库时销毁账本，将 `4 KAS`（`2 + 2`）状态押金全额退还首购买家。
