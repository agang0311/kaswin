# 交易报价：探测网络并选择经济/快速手续费（2026-10-10）

范围：网页脚本与测试。不改 SIL、Profile、核心库、预算 pin 或 SDK；本轮没有签名或广播。

## 依据（rusty-kaspa v2.1.0，`01b532e8`，线上 TN10 节点版本）

- 估计曲线（`mining/src/feerate/mod.rs`）：time(f) = c1 + c1·c2 / f^3（ALPHA=3，`frontier/selectors.rs`）。priority 档 = 预计下一块，normal = 一分钟内（且 ≥ 0.66 分位），low = 一小时内（且 ≥ 0.25 分位），都不低于最低标准费率（`minimum_relay_transaction_fee/1000` = 100 sompi/gram）。
- 待打包交易总质量 ≤ 一个区块（500,000）时，出块模板直接全部打包，不看费率（`frontier.rs` `build_selector` / `TakeAllSelector`）。
- 入池门槛只看 max(compute, normalized transient)（`check_transaction_standard.rs`）；排序看含存储质量的 max（`feerate_key.rs`）。
- `getFeeEstimateExperimental {verbose:true}` 额外返回待打包笔数与总质量；节点不支持时退回 `getFeeEstimate`，不显示内存池规模，也不猜测。

线上只读探测（2026-10-10）：01:58Z 压测中，待打包 1792 笔 / 3,440,070 g（约 6.9 块），low/normal/priority ≈ 112/159/229；数秒后，以及 02:29Z，待打包 90 笔 / 146,160 g，三档都是 100（空闲）。

## 行为

每次报价都会调用 `getFeeEstimateExperimental` 探测，并在同一份实时状态上生成两份完整报价（各自配资、各自收敛）：

| 档位 | 费率 | 质量 | 含义 |
|---|---|---|---|
| 经济 | 节点 low 档 | max(compute, transient)，即入池门槛 | 不为存储质量付费。空闲时和快速档一样会被打包；繁忙时存储质量大的交易排序靠后，可能排队较久 |
| 快速 | 节点 normal 档 | 含存储质量的排序质量 | 繁忙时也按正常顺序打包；超过 0.5 TKAS 时封顶，并在卡片上注明 |

- 两档费用相同时（计算量主导的交易）只显示一档。
- 推荐规则：两档同价、网络空闲，或按节点曲线经济档预计一分钟内打包时，推荐经济档；网络繁忙且经济档排序费率低于 low 档时，推荐快速档。默认选中推荐档，不记住上次的选择，以免空闲时多付。
- 预计等待时间来自节点曲线（由 priority、low 两点拟合，normal 档用来交叉验证误差，在 2% 以内）。只用于显示，金额仍按 bigint 计算。网络繁忙且费率低于 low 档时显示“要等网络空闲”，不给具体数字。
- 切换档位会生成新的计划 id，旧计划作废，批准复选框重新清空，保证批准的就是屏幕上显示的费用和输出。记录中保存所选档位。
- 加速（RBF）沿用原规则，不提供档位选择。

示例（压测繁忙，创建轮次并登记）：经济 0.0031 TKAS（排序 0.77 sompi/gram，要等网络空闲），快速 0.5 TKAS（推荐；按节点费率需约 0.5 以上，已封顶）。
