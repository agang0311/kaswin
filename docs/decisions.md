# 决策与实施门槛

## 用户已确认

Kaswin 为新项目，旧项目 kaswin-archived。任何人可创建，公平透明、无法由特权或协议漏洞操控、纯链上、单网页、所有生效操作链上可查。先设计再实现；从 A 型起步，未来逐步增加其他抽奖类型。只保留能论证保护核心价值或完整性的测试。

## 当前建议，不冒充已批准参数

单状态 UTXO 串行购买、小规模、单赢家、不转让、不滚存、不抽成、分享链接进入。创建者预付储备，参与者票款与手续费分离。不建独立 Worker/Indexer 产品、公共大厅或通用玩法引擎。具体容量、期限、金额与费用须在资源和活性分析后冻结。

## 推进次序

1. 固定来源核验：随机锚所需 opcode、CLTV/sequence 与输入 DAA 的区别、编译器/节点版本匹配。
2. 完成 A 型状态/资金约束与攻击分析，解决 type-a.md 的三个阻塞点。
3. 主助手依据用户核心要求决定并记录取舍，持续设计、不逐项询问；无法满足核心要求则标记阻塞，不以可信后台替代。
4. 锁定协议身份与工具链，写最小真实 VM 正负例，测最坏合法交易资源。
5. 实现链上读取/重建和最小单页生命周期，再经明确授权做 TN10 网络验证。

当前已开始步骤 1，见 [时间/链锚核验](feasibility-01.md)：链锚有执行深度窗口，满额后长期无人推进的安全终结尚未解决。无编译器选择、无 artifact、无主网或测试网部署承诺。“无法操控”是攻击模型下需要证据支持的目标，不是对矿工、共识重组与数据可用性做绝对保证。

## R1：链锚过期的候选解法

主助手决定研究[旧目标与新验证锚分离](randomness-recovery.md)：不更换开奖事件，以近期 commitment 证明同一个历史目标。优先比较有界分步递推，不先引入 ZK 框架。上游 proving-spec 仍为 Reserved，长期费用、数据取得、恶意游标与矿工偏置未解决，不能据此冻结正式算法或宣称已可用。

## R2：证书与奖池分离

[核心方案](core-resolution.md)将恢复证明的竞争状态从奖池中分离：执行者自费并行证书，不能抢占奖池进度；固定开奖目标而更新验证锚。明确两个首先验证的缺口：证书 genesis/谱系身份不可伪造，以及不消费奖池时对 SEALED 创建 DAA/边界的链上认证。矿工偏置和无条件活性不声称已解决。当前仍是设计，不开放资金。

## R3：成本门槛，R1/R2 降为备用研究

用户强调证明过重则无人执行；[成本审查](recovery-cost-decision.md)将 R1/R2 从首版主路径移除，保留材料不删除。新发现 KIP-21 shortcut 可优化部分历史追溯，但不是常数大小证明，且存在尾部与取数接口问题。不得以有限步、奖励或窗口外退款冒充经济可行且公平的恢复。

## 执行与交付决定（用户新增要求）

最终交付一个自包含 index.html，嵌入应用所需 JS/CSS/WASM/Worker 等实际使用的资源，不依赖项目 CDN；运行时仍需用户选择的节点/历史服务和外部钱包授权。单文件是分发边界，不是源码组织方式。离线打开不等于离线参与区块链。

保留源码、设计、必要构建产物和研究中间材料。不引入自动删除旧构建的 clean；产物按版本/内容身份区分，避免把过期 artifact 当成当前协议。尚不建立自动流水线。

主助手负责设计和重大决策，可将明确接口的实现交给指定 gemini-3.8-flash-high subagent。模型与 agent 未确认可用前不派发或换用其他模型。
