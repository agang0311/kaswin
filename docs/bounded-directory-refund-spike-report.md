## 2. 关键历史错误修正与协议语义澄清

### 2.1 修正历史中继底线计算错误 (K=1 与 K=8)
Pinned post-Toccata 标准 Mempool 中继规则：
```text
normalized_transient_mass = transient_mass * 0.5
fee_mass = max(compute_mass, normalized_transient_mass)
relay_floor = max(100_000, fee_mass * 100_000 / 1000)  [即 100 sompi/gram]
```

#### K=1 历史错误修正：
在之前报告中对于全目录 (9,216B) 下的 K=1 交易，曾出现 `2,051,400 sompi` 或 `2,051,400 ~ 2,598,700 sompi` 的模糊表述。
- **真实数据**:
  - 交易大小: `10,257 bytes`
  - 瞬态质量: `transient_mass = 41,028` (折算后 `normalized_transient_mass = 20,514`)
  - 计算质量: `compute_mass = 25,987` (在 Budget 7 下)
  - 费用质量: `fee_mass = max(25,987, 20,514) = 25,987 grams`
  - **标准中继底线**: **`relay_floor = 2,598,700 sompi`** (`0.025987 KAS`)。
- **结论**: 废除所有模糊写法，确认为 `2,598,700 sompi`。

#### K=8 历史错误修正：
此前报告曾声称“K >= 8 即可自给中继”，该结论**确定性错误并被彻底删除**：
- 在 `MAX_REFUND_FEE = 250,000 sompi` 约束下，K=8 批次的最大允许扣费能力为:
  `8 * 250,000 = 2,000,000 sompi` (`0.020 KAS`)。
- 而全目录下 K=8 非终结步的真实 `relay_floor = 3,101,300 sompi` (`0.031 KAS`)。
- **赤字**: `2,000,000 - 3,101,300 = -1,101,300 sompi`。
- **结论**: 全目录下 K=8 **无法**单纯依靠买家扣费达到标准中继底线！已彻底删除所有“K >= 8 可自给中继”的论述。

### 2.2 目录长度真实语义 (Variable-Length Directory)
协议规范澄清：
- 目录不是固定 9,216 字节填充！
- **`directory is variable-length`**:
  `directory_len = purchase_count * 36` 字节 (`1 <= purchase_count <= 256`)。
- 最大目录长度为 `9,216` 字节 (`256 * 36`)。
- 在退款生命周期中，REFUNDING 状态携带该轮真实购买笔数 `P` 条记录，退款过程中保留原始全量 `P` 条记录以支持游标切片，但不包含多余的虚拟记录填充。

## 5. 确定性无死尾调度算法 (Deterministic Non-Dead-End Scheduler)

为了确保任何 `P ∈ [1..256]` 的退款过程都不会留下扣费低于中继底线的危险尾批，客户端必须执行确定性批次调度：

### 5.1 最小批次约束函数 `min_k_for_p(P)`
根据目录大小 `P * 36` 测定覆盖单步中继底线所需的最小买家数：
```rust
pub fn min_k_for_p(p: usize) -> usize {
    if p <= 5 { 1 }
    else if p <= 27 { 2 }
    else if p <= 48 { 3 }
    else if p <= 70 { 4 }
    else if p <= 92 { 5 }
    else if p <= 114 { 6 }
    else if p <= 135 { 7 }
    else if p <= 157 { 8 }
    else if p <= 179 { 9 }
    else if p <= 201 { 10 }
    else if p <= 223 { 11 }
    else if p <= 245 { 12 }
    else { 13 }
}
```

### 5.2 平衡步进调度规则 `schedule_next_k(remaining, p_total, k_max)`
```rust
pub fn schedule_next_k(remaining: usize, p_total: usize, k_max: usize) -> usize {
    if remaining <= k_max {
        return remaining;
    }
    let m = min_k_for_p(p_total);
    let num_steps = (remaining + k_max - 1) / k_max;
    let base = remaining / num_steps;
    let rem = remaining % num_steps;
    let candidate = base + if rem > 0 { 1 } else { 0 };
    candidate.min(k_max).max(m)
}
```
**原理**: 遇到非整除尾数时，算法将剩余记录在剩余步数中均匀平摊，确保每一步的批量大小均落在 `[m..=k_max]` 闭区间内，数学上彻底根除了产生小于 `m` 的死尾批次。

## 10. 退款产品语义与边界说明

1. **规范产品属性**:
   - **Permissionless**: 任何第三方或看守者均可提交合规退款交易。
   - **Self-funded**: 每笔退款交易由批次内买家本金分摊网络矿工费，无需外部资金注资。
   - **Deterministic**: 调度步数与参数完全由链上状态决定。
   - **Resumable / Eager-Prebroadcastable**: 支持客户端预广播整条依赖链，若中断可在任意游标安全恢复。
2. **严禁的不实承诺**:
   - 不承诺“无人值守全自动绝对退款”（Mempool 存在驱逐或重启丢失可能，仍需至少有一方客户端发起交易）。
   - 不承诺节点永久保存依赖交易链。
