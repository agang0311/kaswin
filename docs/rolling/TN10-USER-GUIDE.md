# Rolling TN10 实验页：使用说明

> **这是 Testnet 10 实验版，不是主网。** TKAS 没有真实价值。证据状态 `UNVALIDATED`：合约还没有经过完整验证，不要在这里放任何有价值的东西。

## 开始之前

- **只用一次性的 TN10 私钥。绝对不要粘贴主网私钥或任何有真实资产的密钥。** 页面把私钥只放在浏览器内存里，读取后清空输入框，不写盘、不上传；刷新或关闭标签页后需要重新输入。但你仍是在别人提供的页面里输入私钥，所以只用测试币。
- 你需要自己准备 TN10 私钥（64 位十六进制）和 TKAS 测试币，本页不提供水龙头。创建一轮至少要约 4.5 TKAS；购票要票款加网络费。
- 页面只能连 Testnet 10。节点和预算服务默认已填好，打开后右上角的状态应变成“Testnet 10 · 已连接”。如果显示“连接失败，点此处理”，点它进入“高级设置”检查地址。
- **请随时导出轮次**（轮次页的“更多 → 导出轮次文件”或“高级设置 → 导出全部轮次”）。轮次记录只存在你浏览器的本地存储里，清除浏览器数据就没了。资金仍在链上，但页面没法自己从链上找回这一轮。

## 页面怎么用

顶部有四个入口：**轮次**（你创建或加入的轮次）、**创建**、**我的**（钱包与交易记录）、**规则**（规则与已知限制）。右上角依次是节点状态、GitHub 源码仓库、高级设置、明暗主题、`EN` / `中文` 语言切换和钱包按钮。语言偏好保存在当前浏览器；切换时原地更新显示文案，保留已填表单和当前弹窗。

1. **连接钱包**：点“连接钱包”。粘贴 TN10 私钥可以创建、购票、封盘、开奖；只填一个收款地址则只能做不需要签名的派奖/退款，执行者奖励会发到该地址。
2. **创建轮次**：填票价（≥1 TKAS）、票数上限、开奖最低票数（≥3）和“最早可封盘时间”（预设或自定义分钟数）。右侧实时预览票款、中奖概率、封存分片数和你要付出的押金（4 TKAS，派奖或无人购买时全额退回）。点“核对并报价”，页面会向节点查费率并弹出确认窗口。
   - 票数上限最高可设到 **65,536 张**（协议上限：256 个封存分片 × 256 笔购买）。Testnet 10 上只完整实测到 515 张、2 个封存分片的派奖与退款；超过 515 张时创建页会标出“超出已验证范围”，更大的轮次要分很多批执行派奖/退款，这些路径尚未经实链验证。
3. **轮次页**：顶部是进度条（创建·售票 → 封盘 → 派奖/退款 → 完成）和票款、售出/上限、你持有的票数。工具栏只保留一个“刷新状态”入口，同时追赶最新进度并向节点核对；点“更多”打开操作弹窗，其中提供“复制分享链接”和“导出轮次文件”，安卓和桌面使用相同入口。“下一步怎么做”里只会出现当前阶段能做的操作；暂时做不了的会置灰并写明原因（例如“还差多久可封盘”）。下方是交易记录和规则与链上标识（点“技术信息”可看完整 CID）。
4. **确认窗口**：每笔交易发送前都会列出“你将支付 / 预计收到”、网络费和**资金去向**（每个输出的角色与地址，标出哪些是你的）。核对后点“确认并签名发送”；页面在本地签名并验签，再用脚本引擎检查已签名交易，保存记录后才提交给节点。
5. **高级设置**：节点地址、预算服务地址、备份与恢复、运行日志（不含私钥）。一般不需要改。填了新地址后，页面会先检查格式并实际连接，**只有连接成功的新地址才会保存**，失败时保留原配置并在面板里写明原因；只保存你改过的字段。

## 一轮的流程

| 步骤 | 动作 | 谁能做 | 需要钱包 |
|---|---|---|---|
| 创建 | 创建轮次 | 创建者 | 需要 |
| 购票 | 购买票 | 任何人 | 需要 |
| 封盘 | 封盘 | 任何人（到最早封盘时间，或票售满后） | 需要（付网络费） |
| 开奖 | 开奖 | 任何人（封盘后约 100 DAA，约十几秒） | 需要（付网络费） |
| 派奖 | 派奖：处理已封存的分片 / 结算 | 任何人 | 不需要签名 |
| 退款 | 退款：已封存的分片 / 当前分片 | 任何人 | 通常不需要签名 |
| 超时 | 超时转退款 | 任何人（封盘后约 12 小时无人开奖） | 需要；此路径未经实测 |

- 总票数达到开奖最低票数才会开奖；不足则封盘后进入退款，每条购买记录扣 0.02 TKAS 执行费。
- 每个“分片”最多 256 笔购买，满了会自动封存并开新片；派奖和退款按分片分批执行，大轮次要点多次。
- 派奖和退款对任何人开放，执行者能拿到协议规定的小额奖励。所以即使创建者消失，别人也能把一轮结清。
- 网络费在确认窗口里明确报价。常见在 0.01–0.02 TKAS 左右，退款旧分片的单笔可能到约 0.37 TKAS。

## 多人参与同一轮

页面不能自己从链上追上别人的操作（暂无公共索引），多人共用一轮靠分享链接：

1. 创建者在轮次页点“**更多 → 复制分享链接**”，发给其他参与者。（链接很长时，部分聊天软件可能截断，这时改用“更多 → 导出轮次文件”发送文件。）
2. 其他人打开链接，或在“轮次”页的“加入朋友的轮次”里粘贴，点“加入”。导入的数据是**未认证**的：页面会立即向节点核对（轮次页会显示“已向节点核对”或“与链上状态不一致”），并且在每次操作前再核对链上 UTXO。也可以随时点“刷新状态”。
3. 有人买票后，别人的本地状态就过期了。再操作时会弹出“这一轮的状态已更新”：向刚操作过的人要最新的分享链接，点“粘贴最新分享链接”导入后再继续。
4. **两个人同时买同一轮**：一笔会被接受，另一笔被节点明确拒绝（输入已被花掉），不会扣款。被拒的一方：在轮次页点“放弃这笔”（页面会核对确实没被接受、也不在内存池），再导入对方的最新状态，然后重新购买。

## 交易状态与常见提示

| 提示 | 含义 | 该怎么做 |
|---|---|---|
| 确认中 | 交易已进入选中链，可以继续下一步；满约 100 DAA 后页面自动复核成“已接受” | 不用管 |
| 已接受 | 深度 ≥ 100 DAA 后重新核对通过 | — |
| 这一轮的状态已更新（`STALE_INPUT`） | 本地状态落后于链上 | 向对方要最新分享链接并导入 |
| 这笔交易被节点拒绝 | 例如输入已被别人花掉 | 点“放弃这笔”，导入最新状态后重来 |
| 这笔交易被节点拒绝：你钱包里的一笔资金已被另一笔还没确认的交易占用 | 同一个钱包在别的页面、标签页或脚本里同时操作，两边选中了同一笔资金；节点没有收下这笔，不会扣款 | 点“放弃这笔”，等那笔确认（几秒到一分钟）再重新操作 |
| 钱包里的资金正被另一笔还没确认的交易占用（`WALLET_FUNDS_PENDING`） | 钱包里够用的资金都被未确认的交易占着；页面现在会在准备交易时主动避开这些资金 | 等那笔交易确认后重试 |
| 有一笔交易正在等待确认 | 交易可能已被节点收下，但状态没确认 | **不要重复发起同样的操作**。点“刷新状态”；需要时“重新发送（原签名）”，页面只会重发原来的签名字节 |
| 已停止 | 候选交易被重组挤掉且长时间不在内存池 | 按页面提示处理；不要自己新建替代交易，需让对方发最新分享链接重新导入 |
| 处理中… | 正在准备、签名、发送或处理你刚发起的操作；相关按钮会禁用并显示原因 | 等进度完成；仍可浏览、切换页面。后台接受状态核对本身不会禁用购买等按钮 |
| “资源上限”，且在仅收款地址模式退款 | 这一批退款可能需要测试币辅助执行 | 在钱包中切换为有余额的 TN10 内存钱包后重试；构造报价时的这类失败不会发出交易 |
| “还差 …”的动作 | 时间条件未到 | 等待；页面空闲时每 8 秒自动刷新 |
| 无法自动确认这笔交易（`SEARCH_RANGE`） | 交易提交后离线太久（约 11 小时以上），节点已无法回溯查询 | 先点“重新发送（原签名）”或普通的“放弃这笔”——只要还有一个输入没被花掉，页面就能证明它没成功；若所有输入都已被花掉，才会提供“强制放弃”，放弃后导入最新分享链接 |

## 已知限制

- 证据状态是 `UNVALIDATED`，只在 TN10 做过实验，没有主网。
- 外部钱包（KasWare、Kastle）没有接入，只能用内存里的 TN10 私钥。
- 未经实测：两个节点各收一笔冲突交易的真竞争、三个以上买家同时抢同一轮、超时转退款路径、3 个及以上冻结分片（约 768 笔购买以上）的派奖批次、链重组下超出已观测深度的恢复。因此票数超过 515 张的轮次，创建页会标出“超出已验证范围”。
- 没有公共索引：不能按地址或轮次搜索，“轮次”页只显示你创建或加入的轮次，必须靠分享链接/导出导入。
- 实验页，可能随时调整或下线；下线不影响链上资金的退出路径（派奖/退款对任何人开放），但你需要保留自己导出的轮次。

## 想核对页面没被篡改

页面是单个 HTML 文件，发布时附有 sha256。你可以下载后自行计算（例如 `curl -s <页面地址> | sha256sum`）并与发布的哈希比对。发布清单见 [TN10-HANDOFF.md](TN10-HANDOFF.md) 的“交付物”一节。
