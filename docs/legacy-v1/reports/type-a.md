# A 型：满额开奖 / 未满退款

草案 0.1，2026-09-05 UTC。这是目标语义，不是已证明能编译的合约规格。符号状态不意味着每个都需要一个独立 artifact。

## 角色与不变配置

任何人可创建，创建者无后续特权。任意执行者可按规则推进，奖金只能支付票权归属者。建议配置仅开放经验证范围内的票价、总票数和未满退出期限；不允许自选随机算法、公钥 oracle 或任意脚本模板。参数上限未定。

轮次创建时固定协议类型/版本、唯一身份、票价、总票数、退出规则、随机规则、费用规则及储备回收归属。单票同价；购买可含多张，票权暂不转让。设计采用创建者预付初始执行储备，具体参数待资源分析；储备不能代替未来有人执行的活性论证。

## 状态转换

| 当前 | 动作 | 后继与约束 |
|---|---|---|
| 无 | create | OPEN，配置与储备固定，禁止预铸未付款票 |
| OPEN | buy | 未满仍为 OPEN；付款与新增票权原子绑定 |
| OPEN | buy 最后剩余票 | SEALED；同一交易固定全体票权，不能再 buy |
| OPEN | beginRefund | 仅满足未满退出条件；冻结退款集合为 REFUNDING，不能再 buy 或 draw |
| OPEN 且零购买 | recoverEmpty | 按规则回收储备并终止，不能提取不存在的票款 |
| SEALED | draw/必要重试 | 按唯一证据计算结果；需原子或不可改变随机序列的状态转换 |
| SEALED/开奖中 | pay | PAID，唯一赢家获得票款奖池，储备按预定规则处理 |
| REFUNDING | refund | 按票权退本金，已退不得重退，最终 REFUNDED |

开奖与派奖尽量同交易，不为展示日志额外拆交易。退款逐笔、批量还是一笔完成尚未决定，必须覆盖所有允许的购买分布。终局不能再恢复为售票或另一个终局。

## 资金账本

令 P 为票款本金、C 为执行储备。买票使 P 精确增加 `price × count`；外部输入、找零与网络费逐项约束，不能悄悄侵蚀 P。满额奖池为总票数乘票价；默认无平台抽成。成功结束时本金全额支付赢家，未满退款目标是原票款退回归属者，费用不隐式扣票款。

C 来源、每步预算、允许补费方式与剩余回收归属须明确。不能允许公开 close 入口把 C 抽走，不能仅证明平均 mass 即认定可执行。若资金储备不足导致任一正常合法状态无退出路径，该参数/设计不可开放创建。

## 三个阻塞点

1. **时间/购买竞争**：到达退款条件后，未满 OPEN 的购买和退款可能竞争。不能假定交易 locktime 提供当前时间上界。需证明补满后随机仍不可知，并选择明确的准入语义；暂以“到达退款条件可发起退出”研究，不宣传为严格自动截止；主助手负责论证竞争安全并记录取舍。
2. **公平随机**：必须在票权集合固定之后取得随机信息。固定历史区块、公开可恢复 oracle、可选择种子均不能满足目标。链锚方案须验证唯一选取、执行上下文、重组和矿工偏置，不以 rejection sampling 代替这些论证。
3. **满额后的活性**：不提供任意的看结果退款。随机证明不可得、资源超限、无人出费时的安全退出/持续推进尚未解决；不解决则不得实现为可接收资金产品。

最新固定源码核验见 [可行性 01](feasibility-01.md)：链锚存在执行深度限制，保存 header 本身不能解决超窗，开奖算法暂不冻结。

## 链上可查

每个生效动作都可沿轮次 lineage 验证交易、输入输出、前后配置/票权/资金、随机证据和终局。metadata 只用于发现，不证明事实。真实身份/广播者不是默认可知信息；钱包拒绝签名等本地动作不上链。

必须定义完整历史重建所需的交易/见证、可替换历史来源、验证导入档案与 acceptance/reorg 对账。链上承诺不保证原文可获得，任意裁剪节点不保证永久保留历史。网页能显示未知与撤销，不盲信某个 REST 的“成功”。
