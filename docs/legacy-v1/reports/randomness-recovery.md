# 随机证据恢复：保持旧结果，更新验证锚

2026-09-05 UTC，设计候选 R1。不是已实现、已证明安全或可部署方案。

## 设计突破点

旧随机区块不可再被 OpChainblockSeqCommit 直接查询，不等于旧事件在密码学上不能再证明。必须区分：

- **开奖目标 T**：由固定票据集合及协议边界唯一决定，永久不换。
- **验证锚 R**：调用时仍在可访问窗口内的近期 selected-chain 区块，只负责证明历史事实。

更新 R 不能更新 T、票据集合或随机种子，也不能把 R 的哈希混入中奖计算。晚执行必须得到同一个 T 的同一个结果（相对于同一最终 canonical 历史）。

## 固定来源与限制

KIPs 快照 e4ae2332117b5cb68bd6188e065ef885b6d17939：

- [seqcommit accessor](https://github.com/kaspanet/kips/blob/e4ae2332117b5cb68bd6188e065ef885b6d17939/kip-0021/seqcommit-accessor.md) 的 Lagging Provers 说明可把更长历史证明衔接到近期锚，窗口仅限制脚本直接访问。
- [KIP-21 §6.6–6.7](https://github.com/kaspanet/kips/blob/e4ae2332117b5cb68bd6188e065ef885b6d17939/kip-0021.md) 定义 selected-parent 递推 SeqCommit(B)=H(SeqCommit(parent(B)),SeqStateRoot(B))，含上下文承诺。
- [proving-spec](https://github.com/kaspanet/kips/blob/e4ae2332117b5cb68bd6188e065ef885b6d17939/kip-0021/proving-spec.md) 在该快照只是 Reserved，未提供可直接采用的 guest、见证格式或节点取数规范。

所以这是一条有一手依据的方向，不是上游已经提供完整恢复 SDK。新规范还须与固定节点实际 hash/encoding 实现逐项对照。

## 两条候选实现路线

### R1a：有界分步验证历史承诺

首次在窗口内用 opcode 验证 R 并把 commitment 固定到证明进度 UTXO；之后每笔交易只验证一小段哈希递推/上下文证据，将游标推进到旧目标。已被链上验证保存的 commitment 后续不需重新调用过期 R。

约束：证明进度不能改写奖池、票据集合、T 选择规则或累计验证内容；只能按固定关系推进，不能回退、跳段或选新 seed。奖池不允许被任意“开始恢复”交易锁到一个攻击者选择的无限工作量游标。

需要证明的关键点：

1. 正确的 selected-parent 递推与上下文编码；普通 DAG 父关系不能代替 selected-parent 关系。不能假设 header 第一个 parent 必为 selected parent。
2. T 的唯一边界跨越，以及冻结票据集合先于随机事件；仅证明“某旧区块在历史中”不够。
3. 首个证明锚与目标的距离预算、并发证明/恶意抢占、可替代证明进度以及不会让已经存在的开奖路径倒退。
4. 从最近锚验证至同一 T 的不同证据必然得到相同结果；重组对已接受证明状态的撤销按共识处理。
5. 哈希算法可由目标脚本/编译器正确表达，最坏证据大小和每步 mass 有界。

优点是可能不需要 ZK prover；缺点是交易次数和历史数据成本可能随离线时间增长。不能以“每步有界”声称总费用有界。

### R1b：压缩历史证明

用经过验证的 proof verifier 验证从 T 到 R 的正确历史与目标选择。R 仍由 opcode 锚定；公开输入绑定 network、protocol、round、冻结票据集合、T 与结果。任何人可生成证明，证明服务不具裁决权。

优点是链上证明大小可能有界。缺点是需要 guest/验证器、完整见证获取与浏览器或外部无信任证明工具；存在 ZK opcode 不代表这些已可用。若浏览器无法自己生成、只能依赖单一项目证明服务，则不满足交付完整性。外部可验证证明可作为加速，不能偷偷变成唯一可用路径。

## 主设计决策

优先研究 R1a 的最小可验证递推；保留 R1b 为成本比较，不先引入证明框架。正常目标仍新鲜时可走短路径，超窗时验证旧 T，而不是换 T。两条路径必须共享相同的种子定义和输出约束。

此方案只处理证据窗口问题，不解决矿工随机偏置、历史见证丢失、长期执行费用。若无见证无法恢复，必须明确数据可用性假设；不得宣称链上哈希保证永久取数。

## 其他问题的同步收缩

- 时间语义暂定义为“未满时，到达边界后允许无许可发起退款”，不是墙钟时刻自动撤销。buy/refund 争用同一 OPEN，仅一个分支被接受；购买满额后必须依赖尚未发生的 T。输入 DAA 的检查可限制部分尾部链，但不包装成严格 acceptance 截止。
- 创建者提供初始储备；长期恢复允许执行者自愿追加外部手续费，不能侵蚀票款、改变结果或给付款者特权。追加资金不保证一定有人付款，所以有限储备无法承诺覆盖任意长历史恢复。
- 逐状态记录未证明义务，不新增后台、不扩展分片、不做伪可投注页面。

## 本轮结论

不再把“链锚过期”当作必然无解；正式研究“旧开奖目标 + 近期验证锚 + 可延续证明”。选择权隔离是核心，证据成本和可获取性是硬门槛。当前只完成来源与设计分析，未写合约、未生成证明、未运行 VM。
