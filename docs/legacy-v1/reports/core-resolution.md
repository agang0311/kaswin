# 核心方案 R2：固定开奖结果，证明与奖池分离

2026-09-05 UTC。主设计结论与证明义务；不是编译/VM/网络验证报告。不把条件性活性说成无条件终结，不把区块熵说成绝对公平。

## 0. 首先纠正问题定义

三个要求不能不带条件地同时保证：①无可信服务；②任何人可无限期不操作/不提供数据；③资金一定在有限时间内完成转移。UTXO 脚本不会自行生成交易，若所有人都不提交交易，任何协议都不可能产生转移。因此可承诺的正确活性目标是：只要网络恢复接受交易、至少一个执行者愿意支付费用且能取得必要见证，任何时刻都存在有限步的唯一结果结算路径；不要求某个特定人按时在线。

另一个独立限制：PoW 生产者能影响区块、交易选择或弃块，公开区块哈希不是信息论无偏的随机源。无偏映射不移除输入偏置。R2 先解决执行者不可选择结果与恢复，不声称已消除矿工影响。

## 1. 核心修改：恢复工作不消费奖池

旧候选将证明游标放入奖池状态，导致攻击者可以抢先启动昂贵/陈旧恢复而阻塞所有人。R2 改为：

- 最后一笔购买原子产生唯一 SEALED 奖池 UTXO，票权集合冻结；没有任何 open/close/top-up/退款入口。
- 任意人独立出资创建 Certificate（证明证书）UTXO，证明过程只花证书资金，不花奖池。
- 同轮可有多个并行证书；不存在全局证明锁、首个执行者资格或唯一 keeper。
- 任意完成的合法证书可与奖池在同一交易被消费，输出唯一赢家，随后奖池终止。其他证书不能再次支付已消费奖池。

这是隔离恢复争用的架构决定，不是增加售票分片。首版可限制每笔一个证明步，暂不优化并行构造。

## 2. 必须防止伪造证书的入口

任意创建者可锁一个与 COMPLETE 相同脚本的输出，因此“脚本长得像证书”绝不是证明身份。

必需的相互验证条件：

1. START 验证输入证书是 covenant genesis 的正确起点，检查 covenant 身份推导/谱系与已批准模板，不接受任意伪造状态或未验证跳入 COMPLETE。具体 genesis/binding 规则要由固定节点与编译器证明。
2. 每步只产生同一受验证谱系的一个 successor，完整冻结 round、SEALED outpoint、network、协议版本、起始锚、目标边界与证明游标。
3. PAY 不只检查证书输出内容：证书输入脚本本身必须在同一交易执行完整终结入口；奖池验证该输入精确 covenant 身份和入口约束对应的状态。不能通过另一个输入/输出混淆授权组。
4. 不允许 certificate 自报“valid=true”或凭调用者提供的 commitment 成为可信状态。

若无法在现有 covenant 原语中实现上述根身份绑定，R2 不成立。此项是首先要做的 VM 负例，不得延后。

## 3. 同一目标，不同近期锚

定义符号：S 为最后购票产生的 SEALED UTXO；d(S) 为节点验证语义下该输出的创建 DAA；Δ 为固定正延迟；B=d(S)+Δ。每个证书必须消费或通过可信输入绑定得到同一个 S 和 d(S)，不能让见证自由声明 d(S)。由于普通证明开始不能花奖池，单纯传递 S 的创建 DAA 不可信；必须使用链上认证的 S 接受/创建证据，或在封盘后执行一个不可重置边界的原子 BIND 入口。BIND 若只引用自己的新创建 DAA 会让执行者无限推迟边界，不允许。

**重要未决点**：证书对 S 创建 DAA 的认证与完整交易接受证明，需要纳入历史证明，不能靠 RPC 自报。在未解决之前不能宣称“最后一买后未来目标”已成立。

T 为满足固定跨界规则的唯一 canonical selected-chain 历史事件。不能使用 target_before_daa 的固定字节切片来假定第一 parent 就是 selected parent。

R 为近期可调用 OpChainblockSeqCommit 的锚，仅验证历史，不参与 seed。late proof 必须与 fresh proof 输出同一 T、同一 E(T)。种子候选为 H(domain || network || round || ticketCommit || B || E(T))，域隔离并不使 E(T) 本身不可操纵。

## 4. 反向递推证书（来源支持，实现待核验）

固定 rusty-kaspa cfafeb4c093fa37a303f1b9f19c58f986b870ce3：

- [hashing.rs](https://github.com/kaspanet/rusty-kaspa/blob/cfafeb4c093fa37a303f1b9f19c58f986b870ce3/consensus/seq-commit/src/hashing.rs) 确认 SeqCommit=H(parentSeqCommit,stateRoot)，stateRoot=H(activityRoot,H(contextHash,payloadRoot))，contextHash 编码 timestamp/DAA/blue score 为三个 LE u64。
- [accessor](https://github.com/kaspanet/rusty-kaspa/blob/cfafeb4c093fa37a303f1b9f19c58f986b870ce3/consensus/src/model/services/seq_commit_accessor.rs) 确认近期 selected-parent 锚的可信读取与深度限制。
- [KIP-21](https://github.com/kaspanet/kips/blob/e4ae2332117b5cb68bd6188e065ef885b6d17939/kip-0021.md) 说明 context 是 selected-parent 的上下文，不能误认成当前接受块 DAA，跨界事件需明确一阶偏移。

START 在有效窗口内取得可信 C_R，后续每一步提供 preimages，重算必须等于当前游标 C_i，才能保存 C_parent。每步哈希工作量有界；R 已被验证保存后无需继续调用它，R 过期不使进度证书自动过期。

终点不仅需要匹配某 DAA，还需认证相邻上下文并证明第一次跨界及 S 的先后关系。跨界前所有已验证 context 必须位于边界一侧，不能跳过合法目标选更早目标。正确性还依赖 canonical 链 context 单调性和确定性，须核对共识实现。

不同 R 引出的合法路径若对应同一 canonical 历史，会到达同一 T；这依赖承诺抗碰撞与每步完备验证。重组可能改变 canonical 历史，此时只能按 Kaspa acceptance 撤销，不能承诺重组前后绝对同一赢家。

## 5. 费用与恢复：保证什么，不保证什么

P=票款本金，C=创建者提供的正常结算储备。证书执行者承担证明费，可在最终支付时获得预先固定且不超过 C 的奖励，剩余 C 返回固定接收者。P 不减少。奖励不随调用者自报步数增加，避免慢证书获利。

证书竞争失败、证据中断的损失仅限证明者资金；证书应提供返回自己储备的路径，该路径不能控制奖池或改变 T。退出证书不等于退出抽奖。

若离线跨度为 n、每步 k，朴素总工作为 O(n/k) 笔，是有限但不统一有界。有限 C 无法支付任意长历史，不能声称固定储备保证永久免费恢复。可选压缩证明只改善成本，不替代数据和安全证明。

## 6. 攻击检查表

| 行为 | R2 约束/剩余风险 |
|---|---|
| 不喜欢结果就换新锚 | R 不进 seed；T 跨界规则必须唯一 |
| 抢先创建超长游标 | 只锁自己的证书资金，别人另起证书，奖池不变 |
| 重启证书让随机边界推后 | 证书绑定同一 S 与认证 B，拒绝自报/可重置边界 |
| 伪造 COMPLETE 输出 | 必须拒绝，无条件接受这种输出会导致盗奖；根身份为首要 VM 门槛 |
| 没人及时冻结随机证据 | 任意晚时刻从近期 R 恢复同一 T；前提是历史见证可得 |
| 输家发起满额退款 | SEALED 不提供退款入口 |
| 矿工弃块/操纵熵 | 未解决；不可用拒绝采样或多区块哈希声称消除 |
| 永久无人付费/所有档案丢失 | 无法无条件保证终结；必须公开假设，不伪装算法问题已解决 |

## 7. 公平性剩余缺口的实质结论

不能把“执行者不能改结果”扩大为“任何人无法操控结果”。要满足产品公平目标，需独立选择并验证可接受的随机威胁模型：

- PoW 熵 + 经济安全上界：必须估算矿工可操纵收益，限制奖池只是候选风险控制，不凭平均区块奖励拍参数。
- 密码学延迟揭示/时间锁：可能减少知晓结果后弃块的优势，但引入顺序工作/证明与硬件假设，尚无已核验实现，不擅自建设新密码系统。
- 外部 VRF/阈值 oracle：有明确外部信任与活性假设，不作为本项目的无信任解法。
- 普通参与者 commit-reveal：最后揭示者可中止，押金只能改变经济动机，不能直接给出绝对不可操纵性。

因此 R2 是解决恢复与选择性中止的更强结构，不是两个核心问题已全部解决的宣言。最先验证 certificate 根身份与 S/B 认证，随后才值得花费 TKAS；未证安全不广播接收资金合约。
